**Gathered:** 2026-03-25

<domain>
## Phase Boundary

Inicializar shadcn-svelte no projeto (criar `components.json`, popular `src/lib/components/ui/`) e refatorar todos os widgets compartilhados existentes para usar primitivas bits-ui internamente, enquanto aplica a identidade visual Prisma (dark theme, magenta/cyan, glows) nos componentes shared e na sidebar — fechando o gap da Fase 1.

**Fora de escopo:** Dashboard page (cards de métricas e gráficos ficam como estão), features de negócio (Merchants, etc.).

</domain>

<decisions>
## Implementation Decisions

### shadcn-svelte Init
- **D-01:** Rodar `npx shadcn-svelte@latest init` na raiz do projeto para gerar `components.json` e estrutura base
- **D-02:** Output path padrão: `src/lib/components/ui/` — sem customização do CLI, importado via alias `$lib/components/ui/`
- **D-03:** Tailwind v4 já configurado com `@tailwindcss/vite` — verificar compatibilidade no init (shadcn-svelte pode assumir PostCSS; ajustar se necessário para o setup de vite plugin)

### Componentes a Instalar
- **D-04:** Instalar todos os componentes que o projeto vai usar nas fases seguintes em uma única passagem:
  - **Essenciais (migração):** Button, Badge, Input, Select, Dialog, Separator
  - **Features seguintes:** Tabs, Table, Calendar, Tooltip, DropdownMenu, Avatar, Skeleton
  - Fases 2–8 encontram os primitivos já disponíveis sem precisar instalar durante execução

### Migração dos Widgets Existentes
- **D-05:** Todos os widgets existentes em `src/app/shared/widgets/` são migrados para usar primitivas bits-ui internamente — nenhum fica com CSS inline puro
  - `ConfirmDialog.svelte` → usa `Dialog` do shadcn/bits-ui (nativo com Escape, focus trap, backdrop)
  - `StatusBadge.svelte` → usa `Badge` do shadcn com variantes por entidade
  - `DataTable.svelte` → usa `Table` do shadcn para markup semântico + mantém `@tanstack/table-core` para lógica headless
  - `Pagination.svelte` → usa `Button` do shadcn para os controles de página
  - `AdminLayout.svelte` → refatorada com identidade Prisma (ver abaixo)
  - Filtros (`SelectFilter`, `SearchInput`, `DateRangeFilter`) → usam `Select`, `Input`, `Calendar` do shadcn

- **D-06:** Widgets **permanecem em `src/app/shared/widgets/`** (mesmos paths de import) — sem quebrar imports existentes nas features. Apenas internamente adotam primitivas bits-ui.

### Identidade Visual Prisma
- **D-07:** Escopo desta fase: AdminLayout/sidebar + todos os widgets migrados + novos shadcn components. Dashboard page fica intocado.
- **D-08:** Sidebar — o que recebe tratamento Prisma:
  - Item ativo ganha glow sutil magenta/cyan na borda esquerda (acento vertical, igual ao line do login)
  - Resto da sidebar permanece como está (dark, tokens existentes)
- **D-09:** Todos os shadcn components instalados devem ser customizados para o tema Prisma (dark background, magenta/cyan como accent, tokens do `app.css`) — não usar o tema padrão cinza do shadcn

### Claude's Discretion
- Configuração exata do `components.json` (baseDir, aliases, style)
- Adaptação das variáveis CSS do shadcn para apontar para os tokens do `app.css` (ex: `--primary` → `var(--color-brand-magenta)`)
- Variantes do Badge por entidade (Merchant, Pagamento, Saque, Disputa, Verificação)
- Estrutura interna do DataTable migrado (props, slots, column defs API) — manter compatibilidade com o que foi definido na Fase 1

</decisions>

## Existing Code Insights

### Reusable Assets
- `bits-ui` v2.16.3 — já instalado, pronto para ser a base dos shadcn components (Dialog, Select, Tabs, etc.)
- `lucide-svelte` v0.475.0 — já instalado, usar em todos os componentes que precisam de ícones
- `@tailwindcss/vite` — Tailwind v4 via vite plugin (não PostCSS) — atenção na configuração do shadcn init
- `src/app.css` — tokens CSS já completos: magenta, cyan, dark neutrals, status colors, shadows com glow, radius scale, fontes

### Established Patterns
- Componentes de UI em `src/app/shared/widgets/` — manter este path nos imports externos
- Svelte 5 com `$state`, `$derived`, `$effect` — todos os componentes migrados devem seguir este padrão reativo
- `@tanstack/table-core` (não `@tanstack/svelte-table`) — manter para lógica de DataTable
- CSS custom properties via `var(--color-*)`, `var(--radius-*)` — padrão a seguir nos componentes shadcn customizados

### Integration Points
- `src/app/features/*/presentation/` — onde os widgets são consumidos (imports de `src/app/shared/widgets/`)
- `src/routes/(admin)/+layout.svelte` — usa AdminLayout, deve funcionar após migração sem alteração de import
- `src/app.css` — onde os overrides de CSS do shadcn (variáveis `--primary`, `--secondary`, etc.) devem ser declarados para sobrescrever os defaults

</code_context>
