Follow `merchantListController.svelte.ts` pattern exactly. Interface:
```typescript
interface PaymentListState {
  payments: Payment[];
  total: number;
  page: number;
  limit: number;
  merchantId: string;
  status: PaymentStatus | '';
  method: PaymentMethod | '';
  dateStart: string | null;
  dateEnd: string | null;
  loading: boolean;
  error: string | null;
}
```
Export `createPaymentListController()`:
- Instantiates `new PaymentService(new PaymentRepository())`.
- Initial state: `payments: [], total: 0, page: 1, limit: 20, merchantId: '', status: '', method: '', dateStart: null, dateEnd: null, loading: true, error: null`.
- `loadPayments()`: builds `ListPaymentsParams` from state (page, limit, merchantId if not empty, status if not empty, method if not empty). Calls `service.listPayments(params)`. On success, sets `payments` and `total`. On failure, sets `error`.
- `setMerchant(id: string)`: sets merchantId, resets page to 1, calls loadPayments().
- `setStatus(s: PaymentStatus | '')`: sets status, resets page to 1, calls loadPayments().
- `setMethod(m: PaymentMethod | '')`: sets method, resets page to 1, calls loadPayments().
- `setDateRange(start: string | null, end: string | null)`: sets dateStart/dateEnd. Does NOT trigger API call (D-19: client-side filter).
- `setPage(p: number)`: sets page, calls loadPayments().
- Returns: `{ get state() { return state; }, loadPayments, setMerchant, setStatus, setMethod, setDateRange, setPage }`.
- Also read `$page.url.searchParams` is NOT done in the controller -- that is handled by the page component on mount.
