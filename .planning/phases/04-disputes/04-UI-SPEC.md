| Role | Size | Weight | Line Height | Font | Usage |
|------|------|--------|-------------|------|-------|
| Caption / Label | 12px (0.75rem) | 400 Regular | 1.50 | Outfit | StatusBadge text, table column headers (uppercase + letter-spacing: 0.05em) |
| Body-sm | 14px (0.875rem) | 400 Regular | 1.55 | Outfit | Table cell data, filter labels, secondary detail values |

**Rules:**
- All status badge text: uppercase, letter-spacing 0.05em (existing StatusBadge style)

- Heading font (Space Grotesk) reserved for card section titles and page h1
- Body font (Outfit) for all data, inputs, dropdowns, breadcrumbs

## Layout Contracts

### Disputes List Page (`/disputes`)
```
Page padding: 48px 24px (matches PaymentDetailPage)
Max-width: 1200px centered (list pages wider than detail)
Primary visual anchor: DataTable with MED row border-left highlight

┌─ Breadcrumbs: "Disputas" (single segment, current page) ──────────────┐
├─ Page title: "Disputas" — Space Grotesk 20px 600 ────────────────────┤
├─ Filter bar (always visible, gap: 16px) ──────────────────────────────┤
│   [Status: select]  [Tipo: select]  [Merchant: autocomplete (optional)]│
├─ DataTable ───────────────────────────────────────────────────────────┤
│   Columns: ID (truncated 8 chars) | Merchant (link) | Tipo (badge)    │
│            | Status (StatusBadge) | Valor (R$) | Data abertura        │
│   MED rows: 3px solid #FF3B5C border-left + pulsing (via rowClass)    │
│   Row click → navigate to /disputes/:id                               │
├─ Pagination ──────────────────────────────────────────────────────────┘
```

**Column ordering:** openedAt DESC (most recent first)
**ID column:** truncated to 8 characters with `#` prefix

### Dispute Detail Page (`/disputes/:id`)
```
Page padding: 48px 24px
Max-width: 900px centered (matching PaymentDetailPage)
Primary visual anchor: Card 1 — Informações da Disputa (entry point)

┌─ Breadcrumbs: "Disputas" > "#abc12345" ───────────────────────────────┐
├─ Card 1: Informações da Disputa ───────────────────────────────────────┤
│   Surface: #0F0F18, padding: 24px, radius: 16px, shadow: md           │
│   Fields: Tipo, Status, Valor, Motivo (reason), ID externo, openedAt  │
├─ Card 2: Timeline ─────────────────────────────────────────────────────┤
│   3 steps always rendered: Aberta → Em Análise → Resolvida            │
│   Connector: horizontal line (desktop) / vertical line (mobile)       │
├─ Card 3: Pagamento Relacionado ────────────────────────────────────────┤
│   paymentId truncated (8 chars) as link → /transactions/payments/:id  │
├─ Card 4: Formulário de Resolução (SUPPORT+ only — hidden for VIEWER)  │
│   Dropdown: status (ACCEPTED | REJECTED | RESOLVED)                   │
│   Textarea: resolução (placeholder: "Descreva a resolução...")         │
│   Button: "Salvar Resolução" — disabled until both fields filled       │
└───────────────────────────────────────────────────────────────────────┘
```

**Card gap:** 32px between stacked cards
**Card style:** background `var(--color-surface)`, border `var(--color-border)`, border-radius 16px (`--radius-lg`), shadow `var(--shadow-md)`

### DisputeTimeline Component
```
3 steps — always rendered regardless of current status:

  [●]─────────────[●]─────────────[○]
  Aberta          Em Análise      Resolvida
  {openedAt}      (sem data)      {resolvedAt or —}

Step states:
  Completed: filled circle (#01FAFB cyan), connector line solid
  Current:   filled circle (#FF00FF magenta) + subtle glow-magenta
  Future:    empty circle (rgba(255,255,255,0.08)), connector line dashed

Circle size: 24px diameter
Connector height/thickness: 2px, width: flexible (fills gap between circles)
Step label: 12px Outfit 400, uppercase, letter-spacing 0.05em, color foreground-secondary
Timestamp: 12px Outfit 400, color foreground-secondary (#9090A8), below label
```

**Step active logic:**
- "Aberta" completed when: always (openedAt always present)
- "Em Análise" active when: `status === "UNDER_REVIEW"` or `status === "ACCEPTED"` or `status === "REJECTED"` or `status === "RESOLVED"`
- "Resolvida" completed when: `resolvedAt !== null`

### DisputeResolutionForm
```
Background: transparent (sits inside Card 4)
Gap between elements: 16px

Label "Status de Resolução" — 12px Outfit 400 uppercase
[Select dropdown — ACCEPTED | REJECTED | RESOLVED]

Label "Texto de Resolução" — 12px Outfit 400 uppercase
[Textarea — min-height: 96px, placeholder: "Descreva a resolução..."]

[Salvar Resolução] — Button primary (magenta gradient)
  Disabled state: opacity 0.38, cursor not-allowed
  Enabled: both status AND resolution text filled (length > 0)
  Loading state: spinner inline, text "Salvando..."
```

## Interaction Contracts

### Row click navigation
- Entire DataTable row is clickable (existing `onRowClick` prop)
- Cursor: pointer on hover
- Row hover: `background: var(--color-surface-elevated)` (no translateY on table rows — only buttons)

### MED row highlight
- Applied via new `rowClass` prop on DataTable
- Class `dispute-row--med` applied when `row.original.disputeType === "MED"`
- CSS: `border-left: 3px solid #FF3B5C; animation: med-pulse 1.5s ease-in-out infinite;`
- Row background: unchanged (decision D-06)

### Timeline steps
- Not interactive — read-only visual component
- No click handlers on timeline steps

### Resolution form submit
- Button enabled only when: `status !== ""` AND `resolution.trim().length > 0`
- On submit: disable fields + show spinner, call PUT endpoint, show toast, navigate on success
- On error: re-enable fields, show error toast, do not navigate

### Post-submit behavior
- After successful resolution: navigate back to `/disputes` list
- Rationale: CONTEXT.md discretion area — redirect to list preferred over in-place update (avoids stale data edge case on resolved dispute)

### Cross-navigation
- Merchant link in list: `href="/merchants/{merchantId}"` — opens in same tab
- Payment link in detail Card 3: `href="/transactions/payments/{paymentId}"` — opens in same tab
- Both links: cyan color (`#01FAFB`), no underline by default, underline on hover
